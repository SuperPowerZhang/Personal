## 1. Rspack

### 概念讲解

Rspack 是字节跳动开源的基于 Rust 的高性能打包工具，设计目标是 Webpack 的替代品（兼容其 API）。

**为什么快：**
- Rust 编写，编译为 native code，无 GC 开销
- 多线程并行（模块解析、代码生成并行）
- 增量编译（持久化缓存）
- 内置 SWC（替代 babel-loader + ts-loader）

**vs Webpack vs Vite：**

| 维度 | Webpack | Rspack | Vite |
|------|---------|--------|------|
| 语言 | JS | Rust | JS (esbuild+Rollup) |
| Dev 模式 | Bundle | Bundle | Unbundled (ESM) |
| 冷启动 | 慢（大项目 60s+） | 快（5-10x） | 快（按需编译） |
| 生态兼容 | — | 兼容 Webpack loader/plugin | 不兼容 Webpack |
| HMR | 慢 | 快 | 极快 |
| 适合场景 | 存量项目 | 存量大项目迁移 | 新项目 |

### 面试问题

**Q: umi → rspack 迁移过程中最大的坑是什么？如何兼容旧 plugin？**

### 参考答案

**迁移核心步骤：**
1. 将 umi 的 webpack 配置导出，分析用了哪些 loader/plugin
2. Rspack 内置了 SWC，可直接替换 babel-loader、ts-loader
3. 对于 CSS，Rspack 内置 CSS 处理（类似 mini-css-extract-plugin）
4. 自定义 Webpack plugin 需检查是否用了 Rspack 不支持的 hook

**常见坑：**

1. **Less/Sass 变量注入**：Rspack 的 less-loader 行为与 Webpack 版有细微差异，`additionalData` 注入全局变量时路径解析不同
2. **Plugin 兼容性**：部分 Webpack plugin 依赖了内部 API（如 `compilation.hooks.processAssets` 的 stage），Rspack 未完全实现
3. **CSS Modules 作用域**：生成的 className hash 算法不同，导致快照测试全挂
4. **Dynamic import 路径**：Rspack 对 `import()` 的 magic comments（webpackChunkName）支持不完整

**解决策略：**
- 优先使用 Rspack 内置能力替代第三方 loader
- 不兼容的 plugin 用 Rspack 的 `builtins` 配置替代
- 渐进式迁移：先 dev 环境跑通，再切 production build

### 代码示例

```javascript
// rspack.config.js — 从 webpack 迁移的典型配置
const { defineConfig } = require('@rspack/cli');

module.exports = defineConfig({
  entry: './src/index.tsx',
  output: {
    path: './dist',
    filename: '[name].[contenthash:8].js',
  },
  resolve: {
    extensions: ['.ts', '.tsx', '.js', '.jsx'],
    alias: {
      '@': './src',
    },
  },
  module: {
    rules: [
      {
        test: /\.(ts|tsx)$/,
        use: {
          loader: 'builtin:swc-loader', // 内置 SWC，替代 babel+ts-loader
          options: {
            jsc: {
              parser: { syntax: 'typescript', tsx: true },
              transform: { react: { runtime: 'automatic' } },
            },
          },
        },
      },
      {
        test: /\.less$/,
        use: [
          { loader: 'less-loader', options: { lessOptions: { javascriptEnabled: true } } },
        ],
        type: 'css/module', // 内置 CSS Modules 支持
      },
    ],
  },
  plugins: [],
  builtins: {
    html: [{ template: './public/index.html' }], // 替代 html-webpack-plugin
  },
});
```

## 2. Tree-shaking

### 概念讲解

Tree-shaking 是打包工具移除未使用代码（dead code）的优化技术。基于 ES Module 的静态结构分析。

**前提条件：**
- ESM（`import/export`），不能是 CommonJS（`require`）
- 无副作用（`sideEffects: false`）
- 静态引用（不能 `import(variable)`）

**为什么 Moment.js 难以 tree-shake：**
- Moment 使用 CommonJS 导出
- 所有 locale 文件通过动态 `require` 加载
- 本身是可变对象模式（`moment().format()`）

### 面试问题

**Q: Tree-shaking 原理？为什么 Moment 难以 tree-shake？Day.js 如何解决？**

### 参考答案

**原理：**
1. 构建工具对 ESM 做静态分析，标记每个 export 是否被 import
2. 未被引用的 export 标记为 `unused harmony export`
3. 压缩阶段（Terser/SWC）移除未引用代码

**Moment 问题：**
```javascript
// moment/index.js — CommonJS，导出整个对象
module.exports = moment;

// moment/locale/*.js — 通过目录遍历动态加载
// 打包工具无法确定哪些 locale 未使用
```

**Day.js 解决方式：**
- 核心只有 2KB，功能通过 plugin 按需引入
- ESM 导出，可被 tree-shake
- locale 独立文件，按需 import

### 代码示例

```javascript
// ❌ Moment.js — 无法 tree-shake，全量打包 ~300KB
import moment from 'moment';
import 'moment/locale/zh-cn';
moment().format('YYYY-MM-DD');

// ✅ Day.js — 只打包用到的功能 ~7KB
import dayjs from 'dayjs';
import relativeTime from 'dayjs/plugin/relativeTime';
import 'dayjs/locale/zh-cn';

dayjs.extend(relativeTime);
dayjs.locale('zh-cn');
dayjs().format('YYYY-MM-DD');
dayjs().fromNow(); // 需要 relativeTime 插件
```

```javascript
// 迁移 Moment → Day.js 的常见映射
// moment().add(7, 'days')       → dayjs().add(7, 'day')
// moment().startOf('month')     → dayjs().startOf('month')
// moment().isBefore(other)      → dayjs().isBefore(other)
// moment.duration(5, 'minutes') → 需引入 duration 插件
// moment.tz('Asia/Shanghai')    → 需引入 timezone 插件

// ⚠️ 迁移注意点：
// 1. Moment 是 mutable，Day.js 是 immutable
const m = moment();
m.add(1, 'day'); // m 被修改

const d = dayjs();
const d2 = d.add(1, 'day'); // d 不变，d2 是新对象

// 2. timezone 处理
import utc from 'dayjs/plugin/utc';
import timezone from 'dayjs/plugin/timezone';
dayjs.extend(utc);
dayjs.extend(timezone);
dayjs().tz('Asia/Shanghai').format();
```

## 3. Umi 框架

### 概念讲解

Umi 是蚂蚁金服出品的企业级 React 应用框架，集成路由、构建、部署一体化方案。

### 面试问题

**Q: Umi 的优缺点？为什么从 Umi 迁移出来？**

### 参考答案

**优点：**
- 开箱即用：内置路由、请求（useRequest）、状态管理（dva/model）、国际化
- 约定式路由：`pages/` 目录结构即路由，降低配置心智
- 插件体系：`plugin-access`（权限）、`plugin-layout`（布局）等覆盖企业场景
- 微前端支持：`@umijs/plugin-qiankun` 一键接入

**缺点：**
- 黑盒严重：底层 Webpack 配置被封装，自定义需 chainWebpack 或 hack
- 版本断裂：umi 3→4 breaking changes 多，迁移成本高
- 构建慢：基于 Webpack，大项目冷启动 60s+
- 社区生态：不如 Next.js 活跃，遇到问题参考资料少
- 耦合度高：一旦用了 umi 的约定，很难迁移到其他框架

**迁移动机：**
- 构建速度瓶颈（CI 超时）
- 需要更灵活的自定义能力
- Rspack 可以 10x 提速且兼容大部分 Webpack 配置

## 4. Bundle 分析与优化策略

### 面试问题

**Q: 微前端场景下 bundle 优化的关键策略？**

### 参考答案

**1. 共享依赖外部化**
```javascript
// 主应用将公共库作为 externals，子应用共享
// webpack.config.js
externals: {
  react: 'React',
  'react-dom': 'ReactDOM',
  antd: 'antd',
  dayjs: 'dayjs',
}
```

**2. 按路由 Code Splitting**
```javascript
// 子应用入口按路由懒加载
const routes = [
  { path: '/list', component: React.lazy(() => import('./pages/List')) },
  { path: '/detail', component: React.lazy(() => import('./pages/Detail')) },
];
```

**3. 依赖瘦身**
- moment → dayjs（-300KB）
- lodash → lodash-es + 按需引入（-70KB）
- antd v5 自带 tree-shaking（v4 需要 babel-plugin-import）

**4. 资源分析**
```bash
# webpack-bundle-analyzer
npx webpack --analyze

# rspack 内置
rspack build --analyze
```

**5. 图片/字体优化**
- 小图 inline（< 8KB）
- 大图 CDN + 懒加载
- 字体子集化（仅包含使用到的字符）

## 5. 构建指标采集

### 面试问题

**Q: 如何衡量"构建提速 45s"——指标怎么采集？**

### 参考答案

**采集方式：**

1. **CI Pipeline 时间**：GitLab CI/GitHub Actions 自带 job duration
2. **Webpack/Rspack 插件**：
```javascript
// 自定义计时插件
class BuildTimerPlugin {
  apply(compiler) {
    let startTime;
    compiler.hooks.compile.tap('Timer', () => {
      startTime = Date.now();
    });
    compiler.hooks.done.tap('Timer', (stats) => {
      const duration = Date.now() - startTime;
      console.log(`Build time: ${duration}ms`);
      // 上报到监控平台
      reportMetric('build_time', duration, { project: 'finance' });
    });
  }
}
```

3. **Speed Measure Plugin**：分析每个 loader/plugin 耗时
4. **对比方法**：
   - 同一分支、同一机器（CI runner），切换构建工具前后各跑 5 次取平均
   - 记录冷启动（无缓存）和热启动（有缓存）两种场景

**你的数据：**
- Finance 单模块：umi 构建 ~75s → rspack 构建 ~30s → 节省 45s
- 全域 6 模块：总计节省 4.5min，优化约 40%
- 全量构建（所有模块并行）：最快 5 分钟内完成

## 6. 首屏性能优化

### 面试问题

**Q: Moment→Day.js 迁移使 Bundle 减少 1.12MB，还有哪些首屏优化手段？**

### 参考答案

**优化手段分层：**

| 层级 | 手段 |
|------|------|
| 网络层 | CDN、HTTP/2、Gzip/Brotli、预连接 preconnect |
| 资源层 | Code splitting、懒加载、图片压缩、字体子集 |
| 缓存层 | 强缓存(contenthash)、Service Worker |
| 运行时 | 预渲染/SSR、骨架屏、Critical CSS 内联 |
| 框架层 | React.lazy、虚拟列表、减少 re-render |

### 代码示例

```javascript
// 1. 路由级 Code Splitting
const List = React.lazy(() => import(/* webpackChunkName: "list" */ './pages/List'));

// 2. 预加载关键资源
// <link rel="preload" href="critical.css" as="style">
// <link rel="preconnect" href="https://cdn.example.com">

// 3. 图片懒加载
function LazyImage({ src, alt }) {
  const ref = useRef(null);
  const [loaded, setLoaded] = useState(false);

  useEffect(() => {
    const observer = new IntersectionObserver(([entry]) => {
      if (entry.isIntersecting) {
        setLoaded(true);
        observer.disconnect();
      }
    });
    if (ref.current) observer.observe(ref.current);
    return () => observer.disconnect();
  }, []);

  return (
    <div ref={ref}>
      {loaded ? <img src={src} alt={alt} /> : <div className="skeleton" />}
    </div>
  );
}

// 4. Bundle 分析后针对性优化
// package.json 中配置 sideEffects
{
  "sideEffects": [
    "*.css",
    "*.less"
  ]
}
```
